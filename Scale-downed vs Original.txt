1. OVERVIEW
================================================================================

This document compares four CNN architectures designed for Analog Devices' 
MAX78000 and MAX78002 AI accelerators:

- AI87 models: Full-featured designs for MAX78002 (larger memory, depthwise support)
- AI85 models: Scaled-down designs for MAX78000 (512KB limit, no depthwise support)

Target Dataset: CIFAR-100 (32x32 RGB images, 100 classes)

Key Constraint Differences:
- MAX78002: Larger memory, supports depthwise separable convolutions
- MAX78000: 512KB CNN memory, standard convolutions only

2. AI87 MOBILENETV2 (ORIGINAL - MAX78002)
================================================================================

Device: MAX78002
Architecture: True MobileNetV2 with ResidualBottleneck blocks
File: ai87net-mobilenet-v2.py

ARCHITECTURE DETAILS:
--------------------

Pre-stage (Stem):
  Input: 3 channels (RGB)
  Output: 32 channels
  Operation: Conv2d 3x3, padding=1, stride=1, ReLU

Bottleneck Settings (7 stages):
  Format: [num_repeat, in_channels, out_channels, stride, expansion_factor]
  
  Stage 1: [1, 32, 16, 1, 1]
    - 1 bottleneck block
    - 32 → 16 channels
    - Stride 1 (no downsampling)
    - Expansion 1x (no expansion in first stage)
    
  Stage 2: [2, 16, 24, 2, 6]
    - 2 bottleneck blocks
    - 16 → 24 channels
    - Stride 2 (downsample via first block)
    - Expansion 6x (16 → 96 → 24)
    
  Stage 3: [3, 24, 32, 2, 6]
    - 3 bottleneck blocks
    - 24 → 32 channels
    - Stride 2 (downsample via first block)
    - Expansion 6x (24 → 144 → 32)
    
  Stage 4: [4, 32, 64, 2, 6]
    - 4 bottleneck blocks
    - 32 → 64 channels
    - Stride 2 (downsample via first block)
    - Expansion 6x (32 → 192 → 64)
    
  Stage 5: [3, 64, 128, 1, 6]
    - 3 bottleneck blocks
    - 64 → 128 channels
    - Stride 1 (no downsampling)
    - Expansion 6x (64 → 384 → 128)
    
  Stage 6: [3, 128, 128, 1, 6]
    - 3 bottleneck blocks
    - 128 → 128 channels (no change)
    - Stride 1 (no downsampling)
    - Expansion 6x (128 → 768 → 128)
    
  Stage 7: [1, 128, 256, 1, 6]
    - 1 bottleneck block
    - 128 → 256 channels
    - Stride 1 (no downsampling)
    - Expansion 6x (128 → 768 → 256)

Post-stage:
  Input: 256 channels
  Output: 1024 channels
  Operation: Conv2d 1x1, ReLU

Classifier:
  Input: 1024 channels
  Output: 100 classes
  Operation: AvgPool 4x4 + Conv2d 1x1
  Wide output: Yes (32-bit)

TOTAL BLOCKS: 17 bottleneck blocks (1+2+3+4+3+3+1)

DEPTHWISE SEPARABLE CONVOLUTION:
  Each ResidualBottleneck contains:
    1. Expand: 1x1 conv (increase channels by expansion factor)
    2. Depthwise: 3x3 depthwise conv (spatial filtering, one filter per channel)
    3. Project: 1x1 conv (reduce back to output channels)
    4. Residual connection (if input/output channels match)

CHANNEL PROGRESSION:
  3 → 32 → 16 → 24 → 32 → 64 → 128 → 128 → 256 → 1024 → 100

SPATIAL DIMENSION PROGRESSION (assuming 32x32 input):
  32x32 → 32x32 → 16x16 → 8x8 → 4x4 → 4x4 → 4x4 → 4x4 → 1x1 → 1x1

KEY FEATURES:
  ✓ Uses depthwise separable convolutions (efficient)
  ✓ High expansion ratio (6x) for feature richness
  ✓ Multiple repeated blocks per stage
  ✓ Residual connections within stages
  ✓ Progressive channel expansion
  ✓ Designed for MAX78002's larger memory

YAML CONFIGURATION INSIGHTS (ai87-cifar100-mobilenet-v2-0.75.yaml):
  - 73 total layers including residual connections
  - Uses depthwise groups (e.g., groups: 24, 72, 120, etc.)
  - Explicit residual connections with passthrough and eltwise add layers
  - Memory offsets alternate: 0x0000, 0x2000, 0x4000
  - Processor masks carefully configured for channel counts

ESTIMATED PARAMETERS: ~2.3 million (full version)
ESTIMATED MEMORY: ~8-10 MB for weights

3. AI87 EFFICIENTNETV2 (ORIGINAL - MAX78002)
================================================================================

Device: MAX78002
Architecture: EfficientNet-v2 with MBConv blocks
File: ai87net-effnetv2.py

ARCHITECTURE DETAILS:
--------------------

Stem:
  Input: 3 channels
  Output: 32 channels
  Operation: Conv2d 3x3, stride=2 or with MaxPool
  
MBConv Blocks (9 blocks):

  Block 1 (MBConv1 - Fused):
    Input: 32 channels
    Output: 16 channels
    Expansion: 1x (no expansion)
    Type: Fused (combines operations)
    
  Block 2 (MBConv4 - Fused):
    Input: 16 channels
    Output: 32 channels
    Expansion: 4x (16 → 64 → 32)
    Type: Fused
    
  Block 3 (MBConv4 - Fused):
    Input: 32 channels
    Output: 32 channels
    Expansion: 4x (32 → 128 → 32)
    Type: Fused
    
  Block 4 (MBConv4 - Fused):
    Input: 32 channels
    Output: 48 channels
    Expansion: 4x (32 → 128 → 48)
    Type: Fused
    Stride: 2 (downsampling)
    
  Block 5 (MBConv4 - Fused):
    Input: 48 channels
    Output: 48 channels
    Expansion: 4x (48 → 192 → 48)
    Type: Fused
    
  Block 6 (MBConv4 - Non-fused):
    Input: 48 channels
    Output: 96 channels
    Expansion: 4x (48 → 192 → 96)
    Type: Non-fused (separate depthwise)
    Stride: 2 (downsampling)
    
  Block 7 (MBConv4 - Non-fused):
    Input: 96 channels
    Output: 96 channels
    Expansion: 4x (96 → 384 → 96)
    Type: Non-fused
    
  Block 8 (MBConv4 - Non-fused):
    Input: 96 channels
    Output: 128 channels
    Expansion: 4x (96 → 384 → 128)
    Type: Non-fused
    
  Block 9 (MBConv4 - Non-fused):
    Input: 128 channels
    Output: 128 channels
    Expansion: 4x (128 → 512 → 128)
    Type: Non-fused

Head (Final Convolution):
  Input: 128 channels
  Output: 1024 channels
  Operation: Conv2d 1x1, ReLU

Classifier:
  Input: 1024 channels
  Output: 100 classes
  Operation: AvgPool + FC
  Wide output: Yes

TOTAL LAYERS: 11 major layers (stem + 9 MBConv + head)

MBCONV STRUCTURE:
  Fused MBConv:
    - Combines expand and depthwise into single 3x3 conv
    - More efficient for smaller feature maps
    
  Non-fused MBConv:
    1. Expand: 1x1 conv
    2. Depthwise: 3x3 depthwise conv
    3. SE (Squeeze-Excitation): Optional attention (disabled here)
    4. Project: 1x1 conv
    5. Residual connection (if applicable)

CHANNEL PROGRESSION:
  3 → 32 → 16 → 32 → 32 → 48 → 48 → 96 → 96 → 128 → 128 → 1024 → 100

SPATIAL DIMENSION PROGRESSION:
  32x32 → 16x16 → 16x16 → 16x16 → 8x8 → 8x8 → 4x4 → 4x4 → 4x4 → 4x4 → 1x1 → 1x1

KEY FEATURES:
  ✓ Uses depthwise separable convolutions
  ✓ Mix of fused and non-fused operations
  ✓ Moderate expansion ratio (4x)
  ✓ Progressive scaling
  ✓ SE attention capability (though disabled for resource constraints)
  ✓ Compound scaling philosophy

ESTIMATED PARAMETERS: ~1.5 million
ESTIMATED MEMORY: ~6 MB for weights

4. AI85 MOBILENETV2 (SCALED DOWN - MAX78000)
================================================================================

Device: MAX78000
Architecture: MobileNetV2-inspired with standard convolutions
File: ai85net-mobilenetv2.py

CRITICAL CONSTRAINT: MAX78000 does NOT support depthwise separable convolutions!
Solution: Replace with standard 3x3 convolutions

ARCHITECTURE DETAILS:
--------------------

Stem:
  conv1: 3 → 24 channels
  Operation: Conv2d 3x3, padding=1, stride=1, BN, ReLU
  
Block 1:
  conv2: 24 → 24 channels
  Operation: Conv2d 3x3, padding=1, stride=1, BN, ReLU
  pool1: MaxPool 2x2, stride=2
  Spatial: 32x32 → 16x16

Block 2 (Inverted Residual Pattern):
  conv3a: 24 → 48 channels (expand, 2x)
    Operation: Conv2d 1x1, padding=0, stride=1, BN, ReLU
  conv3b: 48 → 48 channels (spatial)
    Operation: Conv2d 3x3, padding=1, stride=1, BN, ReLU
    Note: Replaces depthwise convolution
  conv3c: 48 → 32 channels (project)
    Operation: Conv2d 1x1, padding=0, stride=1, BN, ReLU
  pool2: MaxPool 2x2, stride=2
  Spatial: 16x16 → 8x8

Block 3 (Inverted Residual Pattern):
  conv4a: 32 → 64 channels (expand, 2x)
    Operation: Conv2d 1x1, BN, ReLU
  conv4b: 64 → 64 channels (spatial)
    Operation: Conv2d 3x3, BN, ReLU
  conv4c: 64 → 48 channels (project)
    Operation: Conv2d 1x1, BN, ReLU
  pool3: MaxPool 2x2, stride=2
  Spatial: 8x8 → 4x4

Block 4 (Inverted Residual Pattern):
  conv5a: 48 → 96 channels (expand, 2x)
    Operation: Conv2d 1x1, BN, ReLU
  conv5b: 96 → 96 channels (spatial)
    Operation: Conv2d 3x3, BN, ReLU
  conv5c: 96 → 64 channels (project)
    Operation: Conv2d 1x1, BN, ReLU
  Spatial: 4x4 (no pooling)

Final Convolution:
  conv6: 64 → 128 channels
  Operation: Conv2d 1x1, ReLU

Classifier:
  Input: 128 channels, 4x4 spatial
  Output: 100 classes
  Operation: FusedAvgPoolConv2d
  Pool: 4x4 → 1x1
  Wide output: Yes (32-bit)

TOTAL CONVOLUTION LAYERS: 14
  - 1 stem
  - 1 initial block
  - 9 in inverted residual blocks (3 blocks × 3 layers each)
  - 1 final conv
  - 1 classifier conv

CHANNEL PROGRESSION:
  3 → 24 → 24 → 48 → 32 → 64 → 48 → 96 → 64 → 128 → 100

SPATIAL PROGRESSION:
  32x32 → 32x32 → 16x16 → 8x8 → 4x4 → 1x1

KEY MODIFICATIONS FROM AI87 VERSION:
  ✗ NO depthwise separable convolutions
  ✓ Uses standard 3x3 conv instead
  ↓ Reduced expansion ratio: 6x → 2x
  ↓ Reduced repeats: 17 blocks → 4 blocks
  ↓ Reduced channels: max 256 → max 96 intermediate
  ↓ Reduced final layer: 1024 → 128
  ↓ Explicit MaxPool layers for downsampling
  ↓ Removed residual connections (to save memory)

0.75x VARIANT (ai85netmobilenetv2cifar100_m0_75):
  Stem: 3 → 18 channels (0.75x of 24)
  Block channels: 18 → 36 → 24 → 48 → 36 → 72 → 48
  Final: 48 → 96
  Classifier: 96 → 100

0.5x VARIANT (ai85netmobilenetv2cifar100_m0_5):
  Stem: 3 → 12 channels (0.5x of 24)
  Block channels: 12 → 24 → 16 → 32 → 24 → 48 → 32
  Final: 32 → 64
  Classifier: 64 → 100

ESTIMATED PARAMETERS:
  1.0x: ~400K parameters
  0.75x: ~225K parameters
  0.5x: ~100K parameters

ESTIMATED MEMORY: ~1.6 MB (1.0x), ~900 KB (0.75x), ~400 KB (0.5x)

TRADE-OFFS:
  Advantages:
    + Works on MAX78000 (no depthwise requirement)
    + Much smaller memory footprint
    + Faster training
    + Simpler architecture
    
  Disadvantages:
    - Less parameter efficient (more params for same capacity)
    - Lower accuracy potential
    - Standard convs are more expensive than depthwise
    - No residual connections means less gradient flow

7. SCALING STRATEGY ANALYSIS
================================================================================

FROM AI87 MOBILENETV2 TO AI85 MOBILENETV2:
------------------------------------------

1. DEPTHWISE REMOVAL:
   Original: Depthwise 3x3 conv (9 params per input channel)
   Replaced: Standard 3x3 conv (9 × input_ch × output_ch params)
   Impact: ~6x increase in parameters for spatial convolutions
   Reason: MAX78000 hardware limitation

2. CHANNEL REDUCTION:
   Stem: 32 → 24 channels (-25%)
   Bottleneck outputs:
     - 16 → removed
     - 24 → 32 (kept similar)
     - 32 → 48 (kept similar)
     - 64 → 64 (kept similar)
     - 128 → removed
     - 256 → removed
   Final: 1024 → 128 (-87.5%)

3. BLOCK REDUCTION:
   17 bottleneck blocks → 4 blocks (-76%)
   Removed stages:
     - Stage 1 (expansion 1x) → integrated into stem
     - Stage 5 (3 blocks) → removed
     - Stage 6 (3 blocks) → removed
     - Stage 7 (1 block) → removed
   
4. EXPANSION REDUCTION:
   6x expansion → 2x expansion (-67%)
   Example: 24 channels
     - AI87: 24 → 144 → 24 (144 intermediate)
     - AI85: 24 → 48 → 32 (48 intermediate)
   
5. RESIDUAL REMOVAL:
   Original: Residual connections within stages
   Modified: No residual connections
   Reason: Simplify architecture, save memory
   Impact: Less gradient flow during training

6. POOLING STRATEGY:
   Original: Integrated into stride-2 convolutions
   Modified: Explicit MaxPool2d layers
   Reason: MAX78000 doesn't support stride > 1 in conv2d

TOTAL PARAMETER REDUCTION: ~83% (2.3M → 400K)
TOTAL MEMORY REDUCTION: ~84% (10MB → 1.6MB)

------------------------------------------

FROM AI87 EFFICIENTNETV2 TO AI85 EFFICIENTNETV2:
------------------------------------------------

1. MBCONV SIMPLIFICATION:
   Original: Full MBConv with depthwise
   Modified: Expand-Spatial-Project pattern
   
   Original MBConv structure:
     - Expand (1x1)
     - Depthwise (3x3, groups=channels)
     - SE attention (optional)
     - Project (1x1)
   
   Modified structure:
     - Expand (1x1)
     - Standard (3x3, full convolution)
     - Project (1x1)

2. BLOCK REDUCTION:
   9 MBConv blocks → 2 main stages
   Fused blocks → removed (not applicable without depthwise)
   Non-fused blocks → simplified to expand-spatial-project

3. CHANNEL SCALING:
   Early stages: 16-32 → 24-40 (slight increase for compensation)
   Mid stages: 48-96 → kept similar
   Late stages: 128 → 64 (50% reduction)
   Final: 1024 → 128 (-87.5%)

4. EXPANSION ADJUSTMENT:
   Stage 2: 4x expansion maintained (24 → 96)
   Stage 3: 4x → 2x expansion (40 → 80)
   Reason: Balance memory with capacity

5. AGGRESSIVE DOWNSAMPLING:
   Original: 3 stride-2 operations
   Modified: 1 early pool + 2 stage pools
   Effect: Reduces spatial dimensions faster
   Benefit: Less computation, faster inference
   Cost: May lose fine spatial details

TOTAL PARAMETER REDUCTION: ~87% (1.5M → 300K)
TOTAL MEMORY REDUCTION: ~88% (6MB → 1.2MB)

------------------------------------------

COMMON SCALING PATTERNS:
-----------------------

1. Hardware Constraint Adaptation:
   - Replace depthwise with standard 3x3
   - Use explicit pooling instead of stride
   - Simplify residual connections

2. Memory Optimization:
   - Reduce final layer width dramatically (10x reduction)
   - Remove deepest stages
   - Reduce expansion factors
   - Minimize intermediate channel counts

3. Capacity Preservation:
   - Maintain critical bottleneck widths
   - Keep similar number of stages (depth)
   - Preserve expand-project pattern
   - Maintain spatial resolution progression

4. Efficiency Balance:
   - Fewer but wider stages (EfficientNetV2 approach)
   - More gradual scaling (MobileNetV2 approach)
   - Trade-off between depth and width

8. ARCHITECTURE PHILOSOPHY
================================================================================

MOBILENETV2 PHILOSOPHY:
----------------------

Core Concept: Inverted Residuals with Linear Bottlenecks

Key Ideas:
1. Inverted Residual:
   - Traditional residual: Wide → Narrow → Wide
   - Inverted: Narrow → Wide → Narrow
   - Rationale: Keep representational bottleneck narrow, expand for 
     non-linear transformations

2. Linear Bottleneck:
   - Remove ReLU from final projection
   - Preserve information in low-dimensional space
   - Prevent ReLU from destroying information

3. Depthwise Separable:
   - Factorize spatial and channel-wise operations
   - Drastically reduce parameters (9×c vs 9×c²)
   - Enable deeper networks with less computation

AI87 Implementation:
  ✓ Full inverted residual blocks
  ✓ High expansion ratio (6x) for rich features
  ✓ Many repeated blocks for deep feature learning
  ✓ True depthwise separable convolutions
  ✓ Residual connections for gradient flow

AI85 Adaptation:
  ⚠ Inverted residual pattern maintained
  ⚠ Reduced expansion (2x) due to memory
  ✗ No depthwise (replaced with standard 3x3)
  ✗ Fewer blocks (4 vs 17)
  ✗ No residual connections
  → Philosophy preserved but heavily compromised

Impact:
  + Architecture identity maintained
  - Efficiency benefits of depthwise lost
  - Deep feature learning reduced
  - Information preservation via residuals lost

------------------------------------------

EFFICIENTNETV2 PHILOSOPHY:
-------------------------

Core Concept: Compound Scaling with Training-Aware NAS

Key Ideas:
1. Compound Scaling:
   - Scale depth, width, and resolution together
   - Balanced scaling for optimal efficiency
   - Predetermined scaling coefficients

2. Fused-MBConv:
   - Combine expansion and depthwise for small features
   - More efficient than separated operations
   - Adaptive fusion based on feature map size

3. Training-Aware Architecture:
   - Smaller expansion ratios (4x vs 6x)
   - Smaller kernels in early layers
   - Progressive expansion throughout network
   - Optimized for training speed AND accuracy

4. Non-uniform Scaling:
   - Different scaling for different stages
   - Early stages: more aggressive
   - Later stages: more conservative

AI87 Implementation:
  ✓ Mix of fused and non-fused MBConv
  ✓ Moderate expansion (4x)
  ✓ Progressive channel scaling
  ✓ SE attention capability
  ✓ Efficient training characteristics

AI85 Adaptation:
  ✗ No fused operations (incompatible)
  ✗ No non-fused MBConv (no depthwise)
  ⚠ Simplified to expand-spatial-project
  ⚠ Aggressive early downsampling
  ⚠ Only 2 main stages (vs 9 blocks)
  → Philosophy largely abandoned

Impact:
  - Compound scaling not applicable
  - Training efficiency benefits lost
  + Inference speed improved (fewer layers)
  + Memory footprint minimized
  - Architecture sophistication lost

------------------------------------------

COMPARISON OF PHILOSOPHIES:
--------------------------

MobileNetV2:
  Focus: Inverted residuals + Linear bottlenecks
  Strength: Information preservation
  Scaling: Repeat blocks, control width
  AI85 Fidelity: Moderate (pattern preserved)

EfficientNetV2:
  Focus: Balanced compound scaling
  Strength: Training-inference efficiency
  Scaling: Coordinated depth/width/resolution
  AI85 Fidelity: Low (heavily simplified)

AI85 MobileNetV2:
  Retains: Inverted residual pattern
  Lost: Depthwise efficiency, residuals, depth
  Gained: Hardware compatibility
  Philosophy: Pragmatic adaptation

AI85 EfficientNetV2:
  Retains: Expand-project pattern
  Lost: Fused operations, compound scaling, depth
  Gained: Minimal footprint, fast inference
  Philosophy: Extreme simplification
